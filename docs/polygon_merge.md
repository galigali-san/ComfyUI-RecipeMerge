# Polygon LoRA Merge：LoRAを好きな数だけ追加する

Triangle LoRA Mergeの任意入力数版です。既存のTriangleノードとワークフローは残ります。
新しく **Polygon LoRA Merge (Dynamic / Anima / SD)** を追加してください。

## 更新とノード追加（Windows）

`ComfyUI/custom_nodes/ComfyUI-RecipeMerge`で以下を実行します。

```bat
git fetch origin
git switch feat/anima-lora-merge
git pull --ff-only origin feat/anima-lora-merge
```

ComfyUIを完全に終了して再起動し、ブラウザでCtrl+F5を押します。
キャンバスをダブルクリックし、`Polygon`で検索してください。
既存Triangleノードが自動的にPolygonへ置き換わるわけではありません。

## 操作

1. 各行のA/B/C…に、同じアーキテクチャ用のLoRAを選択します。
   新規ノードは一覧の先頭から最大3入力で開始します。
2. **＋ LoRAを追加**でD、E…を増やします。4入力なら四角形、5入力なら五角形になります。
   コード上の固定最大入力数はありません。1入力は点、2入力は線分です。
3. 多角形の点を動かして配合します。頂点はそのLoRA100%、中心は均等配合。
   図形の外を操作した場合は最も近い辺の配合になります。
4. 数値欄でも入力できます。合計は自動的に100%へ正規化されます。
   「均等配合」、各LoRAの「100%」ボタンも使えます。
5. `model`と必要に応じて`clip`を接続して試し生成。
   `save_file=ON`で、連結した新しいLoRAを`models/loras`へ保存します。

**4入力以上では、点の位置だけで任意の配合すべてを表すことはできません。**
ドラッグでは多角形の平均値座標（mean-value coordinates）を使います。
数値入力なら独立に全比率を指定でき、点はその配合の重心を表示します。
同じ点に複数の異なる配合が対応するため、数値入力後に点をドラッグすると配合が変わる場合があります。
三角形では通常の重心座標と一致します。

## 追加・削除したとき

- 追加したLoRAは0%。全体・TE・すべての階層/要素の既存配合を維持します。
- 削除したLoRAの列を全設定から取り除き、残った列を100%へ正規化します。
- 残りの配合が全0%になった設定は、残った先頭LoRAを100%にします。
- 最後の1入力は削除できません。
- 頂点のラベルは並び順に振り直します。残ったファイルと配合の対応は維持します。

## 階層・要素別配合とプリセット

Triangleと同じく、全体・TE・階層・要素・サブ要素を選んで別配合を指定できます。
優先順位は個別階層 > 全階層、同じ階層ではサブ要素 > 要素 > 全要素です。
全体を変えても既存の上書きは変わりません。必要なら上書きを解除してください。
`architecture`を変えたときは、元の階層形式の上書きを解除してから設定し直します。

Anima用途プリセットはA＝残したいLoRA、B＝取り込みたいLoRA、C以降＝0%に展開します。
適用時は全体・TE・階層の上書きを置き換えます。用途名の見た目の効果は未検証です。

## 保存・復元

LoRAのファイル名一覧と全配合はワークフローに保存されます。
「配合JSONを書き出す／読み込む」でも再利用できます。
PolygonプリセットにはLoRA名も含まれ、読込先でそのファイルが必要です。
Triangle配合JSONも読めます。この場合は現在の先頭3入力をA/B/Cとして使い、4入力目以降は外します。
入力名自体は元のTriangle配合JSONに含まれません。読み込む前にA/B/Cを合わせてください。
いずれもarchitectureが一致する必要があります。

ノード内部のpolygon値の例：

```json
{
  "loras": ["a.safetensors", "b.safetensors", "c.safetensors", "d.safetensors"],
  "global": [0.4, 0.3, 0.2, 0.1],
  "te": [1, 0, 0, 0],
  "overrides": {"B03": {"ff": [0.1, 0.6, 0.2, 0.1]}}
}
```

書き出しファイルはこれを`type=recipe_merge_polygon_preset`、`version=1`、`architecture`、`polygon`で包みます。

## 対応範囲と検証

同じモデル構造用の通常LoRAと対応LoConが対象です。チェックポイント本体、LoHa/LoKr/DoRA、tucker形式は対象外。
`ΔW = Σ wi·ΔWi`をrank方向の連結で表し、入力ごとのalpha/rankを反映します。
rankは最大で入力rankの合計になります。入力数が増えるとファイルサイズとメモリ使用量も増えます。
片側にしかないキーは指定比率のまま残し、他の入力へ配合を再配分しません。

CPUの実テンソルで1/2/3/4/5/12/32入力の計算、TE・階層上書き、配列長の不正拒否、保存とプレビューの同一結果をテスト。
座標は1/2/3/4/5/8/20/40入力の頂点・辺・中心・図形外をテスト。
DOMイベントでは入力追加/削除・上書き追従・プリセット・ワークフロー復元をテストします。
既存Triangleの回帰テストも実施。実ComfyUIでの表示・実モデルの画像生成は未確認です。

```text
python test_polygon_merge.py
node test_polygon_math.mjs

```
