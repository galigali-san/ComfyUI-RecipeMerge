# Triangle LoRA Merge (Anima / SD)

LoRA Mergeの3入力版です。同じアーキテクチャ用の通常LoRA/対応LoConをA/B/Cに指定します。
チェックポイント本体のマージ、LoHa/LoKr/DoRA、tucker付きLoCon、異なるアーキテクチャの混合は対象外です。

## 基本操作

1. `advanced/model_merging`から **Triangle LoRA Merge (Anima / SD)** を追加。
2. `lora_a` / `lora_b` / `lora_c`にLoRAを指定し、`architecture`を選択。
3. 三角形の点を動かす。A/B/Cの頂点はそれぞれ100%、中心は各約33.3%。
   数値欄は入力後に合計100%へ正規化します（20/30/50等）。初期値はA100%。
4. `model`（必要なら`clip`）を接続して生成を試す。
5. 納得したら`save_file=ON`で`models/loras`へ保存。同名は連番。配合と入力名をメタデータに記録します。

## 階層・要素の上書き

対象のプルダウンで「全体の基本配合」「テキストエンコーダ」「全階層の要素別」または個別ブロックを選択。
個別階層では全要素、attn1/attn2/ff/norm/proj、q/k/v/outやFFのサブ要素に別の点を設定できます。
全体より個別階層が、同じ階層では全要素より要素、要素よりサブ要素が優先されます。
AnimaはB00〜B27とBASE、SDはIN/OUT/M00/BASEです。
テキストエンコーダはTE設定があればそれを使い、なければ全体を継承します。
「上書きを解除」で選択対象だけ、「全上書きを解除」でTEを含む全設定を基本配合へ戻せます。
対象の編集は他の対象へ自動的に複製しません。

Anima用途プリセットは **A＝残したいLoRA、B＝取り込みたいLoRA、C＝0** に展開します。
用途プリセットの適用は、それまでのTE設定と階層・要素の上書きを置き換えます。
全体だけでCを増やしても既存の上書きには効きません。Cを加えたい対象を選んで操作してください。
用途名は未検証の調整方針であり、塗りや顔等を独立抽出する機能ではありません。

## 配合の保存

ワークフロー保存で配合も保存されます。「配合JSONを書き出す／読み込む」でも再利用できます。
Triangle用JSONは通常の2入力プリセットと別形式です。architectureが一致するファイルを読み込んでください。
JSONを直接編集する場合の例：

```json
{
  "global": [0.6, 0.3, 0.1],
  "te": [1, 0, 0],
  "overrides": {
    "ALL": {"ff": [0.2, 0.7, 0.1]},
    "B03": {"attn2": [1, 0, 0], "attn2.to_q": [0.5, 0.25, 0.25]}
  }
}
```

これはノード内部のtriangle値です。書き出しファイルはtype/version/architecture/triangleで包みます。

## 計算と制約

`ΔW = a·ΔWA + b·ΔWB + c·ΔWC`、`a+b+c=1`。
入力LoRAのalpha/rankを反映してrank方向に連結します。近似圧縮は行いませんが、保存dtypeによる丸めはあります。
rankは最大で3つの合計になるため、ファイルサイズ・メモリ使用量は増えます。
片方にしかないキーはその入力の配合で残り、欠けた入力への再配分は行いません。
不完全なキー・非対応形式・形状不一致はエラーにし、不完全なファイルを黙って保存しません。
配合0の入力のキーはマージに参加しません。
同じ階層構造・形状でも学習元が異なれば互換性や見た目は保証できません。
レポートには配合・入力別使用キー数・最大rank・上書き一致数・プレビュー適用キー数を表示します。
